Agentic engineering

How I build production software with agents.

I treat Claude Code and OpenAI Codex as a small engineering team, not an autocomplete. One agent does the engine and data work; another acts as a review and promotion gate. Nothing reaches a customer without passing that gate. Every build is checked against live sources and a test suite before it ships — I treat agent output as a draft to be proven, not accepted.

The judgment is mine. The clearest example: I use agents to build Lasting Ground, but the engine itself is deterministic. The compliance-critical answers never pass through a language model. In a domain next to insurance and lending, an answer has to be reproducible and traceable to an official source every time, so the model stays out of the hot path and the sources speak for themselves.

I've written this operating model up, with a runnable eval harness, an Agent Skill, and an MCP server, all on synthetic data, so you can inspect the method for yourself.
